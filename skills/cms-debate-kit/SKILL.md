# CMS Debate Kit

도서 발췌문에서 검증 가능한 토론 자료 묶음을 만든다. 사용자가 일부 단계만 요청하면 그 범위만 수행하되 아래 규칙은 항상 적용한다.

## 작업 전 확인과 승인

1. 입력 발췌문, 기존 양식, 토론 규칙, 결과물 폴더와 관련 파일을 읽기 전용으로 확인한다.
2. 생성할 파일, 작업 단계, 예상 결과와 절대 저장 경로를 먼저 제시한다.
3. 파일 생성·수정·이동은 사용자의 명시적 승인 후에만 수행한다. 승인 범위를 벗어나는 변경은 다시 승인받는다.

## 필수 규칙

- 발췌문에 없는 사실, 사건, 인물 정보 또는 해석의 전제를 근거처럼 제시하지 않는다. 책 전체에 관한 기억이나 외부 자료도 근거로 섞지 않는다.
- 필요한 근거를 발췌문에서 찾지 못하면 추측하지 말고 정확히 `발췌문에서 확인 불가`라고 표시한다.
- 직접 인용은 발췌문의 글자와 문장부호를 원문 그대로 옮기고 문단 번호를 함께 적는다. 요약이나 의역을 따옴표 안에 넣지 않는다.
- 원본 파일의 내용과 파일명은 수정·삭제하지 않는다. 변환, 정규화 또는 문단 번호 부여가 필요하면 파생본을 만든다.
- 새 문서, 코드와 리포트는 작업 대상 루트의 `결과물` 폴더에 저장한다. 사용자가 다른 위치를 명시적으로 승인한 경우에만 예외로 한다.
- 기존 결과물을 덮어쓸 가능성이 있으면 먼저 알리고 승인받는다.

## 워크플로우

### 1. 발췌문 준비

- 제목과 메타데이터를 제외한 본문 문단을 순서대로 식별한다.
- 원본에 안정적인 문단 번호가 없으면 원본을 고치지 말고 `결과물/발췌문_문단번호본.md`를 만든다. 비어 있지 않은 본문 문단에 `[1]`, `[2]`처럼 번호를 붙이고 본문 글자는 바꾸지 않는다.
- 판독이 어려운 부분은 임의 복원하지 않고 `발췌문에서 확인 불가`로 기록한다.

### 2. 논제 설계

- 발췌문 안에서 찬성과 반대가 모두 논증 가능하며 가치 충돌이나 판단 기준이 드러나는 논제를 만든다.
- 하나의 판단만 담은 평서형 문장으로 쓰고 핵심 용어, 적용 범위, 찬반별 이용 가능 문단을 점검한다.
- 어느 한쪽의 직접 근거가 없으면 논제를 수정하거나 해당 쪽을 `발췌문에서 확인 불가`로 표시한다.

### 3. 근거카드 작성

- 찬성과 반대 각각에 주장, 직접 인용, 문단 번호, 인용이 주장을 뒷받침하는 이유, 예상 반론과 한계를 기록한다.
- 직접 인용과 해석을 분리하고, 해석은 인용에서 합리적으로 도출되는 범위를 넘지 않는다.

### 4. 활동지와 루브릭 작성

- 활동지는 논제 확인, 근거 탐색, 주장-인용-설명 연결, 반론·재반론, 토론 후 성찰의 흐름을 지원한다.
- 모든 근거 입력란에 원문 인용과 문단 번호 칸을 둔다.
- 루브릭은 근거 정확성, 주장과 근거의 연결, 반론 대응, 참여·경청을 평가한다.
- 근거 정확성의 최고 수준에는 `원문 그대로 인용하고 문단 번호가 정확함`을 포함하고 발췌문 밖 내용을 근거로 사용한 경우 감점한다.

### 5. 인용 검증

- 토론 로그에는 직접 인용을 `근거 원문: <인용문> (문단 N)` 형태로 남긴다.
- `scripts/verify_quotes.py <발췌문.md> <토론로그.txt> <검증리포트.md>`를 실행한다. 원본에 문단 번호가 없다면 문단번호 파생본을 입력한다.
- `✔`는 완전 일치, `△`는 80% 이상 유사, `✖`는 발췌문에서 확인 불가한 인용이다. `△`와 `✖`는 발췌문을 직접 대조한다.
- 자동 결과는 보조 판정이다. 문단 번호, 인용 범위, 발췌문 밖 맥락 사용 여부를 별도로 확인한다.

## 산출물과 완료 보고

파일 구성과 품질 기준은 [references/output-specs.md](references/output-specs.md)를 따른다. 사용자가 제공한 양식이 있으면 그 양식을 우선하되 필수 규칙은 유지한다.

완료 후 생성·변경한 파일 수와 최종 절대 경로를 표로 정리하고 다음 항목을 보고한다.

- 원본 보존 여부
- 모든 직접 인용의 원문 일치와 문단 번호
- 발췌문 밖 근거 또는 `발췌문에서 확인 불가` 항목
- 인용 검증 판정 집계와 사람이 다시 볼 항목
